# Fix Plan: Chatbot Only Responds to First Question

## Root Cause

The Zod validation schema in `src/lib/chat/validation.ts` rejects tool-related message parts. After the AI model calls `searchKnowledgeBase`, the assistant message contains `ToolUIPart` parts (e.g., `{type: "tool-searchKnowledgeBase", ...}`). On the next user message, `useChat` sends ALL accumulated messages including these tool parts. The validation schema only accepts `{type: "text"}`, so it rejects the request with a **422 error**.

**Flow:**
1. User sends Q1 → validation passes (only text parts) → model calls `searchKnowledgeBase` → response streams back
2. `useChat` stores response with `[{type: "tool-searchKnowledgeBase", ...}, {type: "text", ...}]` parts
3. User sends Q2 → frontend sends all messages including tool parts → **validation fails (422)** → error bubble shown

## Files to Modify

### 1. `src/lib/chat/validation.ts` (PRIMARY FIX)

**Problem:** Lines 22-24 use `z.literal("text")` for `parts[].type`, rejecting all non-text part types.

**Fix:** Replace the narrow `parts` schema with a discriminated union covering all AI SDK `UIMessagePart` types:

- `text` → `{type: "text", text, state?}`
- `reasoning` → `{type: "reasoning", text, state?}`
- `step-start` → `{type: "step-start"}`
- `tool-*` → `{type: regex /^tool-.+$/, toolCallId, state?, input?, output?, ...}` (regex handles dynamic tool names)
- `dynamic-tool` → `{type: "dynamic-tool", toolName, toolCallId, ...}`
- `source-url`, `source-document`, `file`, `data-*` → typed schemas with `.passthrough()`

Also raise `parts.max(20)` → `max(100)` for tool-heavy conversations, and `content.max(10000)` → `max(50000)` for longer reasoning.

### 2. `src/lib/chat/validation.test.ts` (UPDATE TESTS)

**Tests to update:**
- **Line 179-190** (`rejects parts with more than 20 items`): Change 21 → 101 to match new `max(100)`
- **Line 192-204** (`rejects parts with non-text type`): This test verifies `{type: "image"}` is rejected. After the fix, `{type: "image"}` will still be rejected (not in the union), but we should also **add new tests** for accepted non-text types:
  - Accepts `tool-*` parts (e.g., `{type: "tool-searchKnowledgeBase", toolCallId: "abc"}`)
  - Accepts `reasoning` parts
  - Accepts `step-start` parts
  - Accepts `dynamic-tool` parts
  - Still rejects truly invalid types like `{type: "image"}`
